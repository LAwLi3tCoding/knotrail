# Knotrail 用户指南

本文描述仓库当前实现。Knotrail 在本地保存任务和证据，通过 pi SDK 调用配置的模型；界面上的状态来自主进程保存的任务快照，不由动画或聊天文本推算。

## 重试时保留研究结果

在右侧规划栏选择步骤，再选择「重做此步骤」。预览会列出重跑与保留的节点，并逐项说明原因。选择「应用并继续」后，仅合格的独立研究保留原 Run 和产物，其余受影响节点重新执行。主对话与规划栏均可展开「已复用研究结果」查看原输入和产物。关闭预览会保持暂停，选择「继续」可按原流程恢复。改变总目标或验收仍会重新规划，规则见 [研究复用](RESEARCH-REUSE.md)。

## 1. 安装与启动

当前执行平台是 macOS。准备 Git、Node.js 24 或更新版本，以及原生依赖编译所需的开发工具。先安装依赖，再启动：

```sh
npm ci
npm run dev
```

`dev` 先构建前端、Electron 主进程、pi 工作进程和执行助手，再启动应用。它不是热更新服务器，修改源码后需要重新运行。

已经构建过时可以运行 `npm start`。如需重新生成产物，先运行 `npm run build`。`npm run package` 会生成未签名的 macOS 应用目录，不包含公证、安装器或自动更新。

应用默认使用 Electron 提供的本机应用数据目录，保存 SQLite 状态、密钥密文、工作区、pi 会话与报告。开发和隔离测试可以通过 `KNOTRAIL_DATA_DIR` 指定另一个数据目录。不要把真实任务数据、密钥或会话目录提交到代码仓库。

同一数据目录只能有一个状态所有者。若启动提示已有所有者，应先确认原应用或任务是否仍运行，不要删除锁文件来绕开运行中的任务。

## 2. 首次配置模型

进入左下角「设置 → 模型」：

先选认证方式。选择「现有 Codex 登录」时，先在本机 Codex 中完成 ChatGPT 登录，再回到 Knotrail 保存模型配置。该模式没有 API 密钥和自定义接口地址输入框，不需要复制令牌。新配置默认填入 pi 目录中的 `gpt-6-astra`，可选择目录内且账户有权使用的模型。

「检查已保存登录」只检查本机登录缓存的格式和到期时间，不发送模型请求。Knotrail 每个 Run 重新读取当前 access token，不复制刷新凭据，也不替 Codex 刷新。到期或缓存不可用时，先在 Codex 更新登录，再在 Knotrail 继续任务。它不将 ChatGPT 订阅转换成 Platform API key。

Codex 模式使用服务规定的输出额度，界面不显示无效的本地上下文/输出上限控件；任务轮数与运行时间预算仍生效。其他服务选择「API 密钥 / 本地服务」，填写下表字段：

| 字段 | 用途 |
| --- | --- |
| 接口地址 | OpenAI 兼容 Chat Completions 服务的基础 URL |
| 模型 ID | 服务商实际提供、支持工具调用的准确 ID |
| API 密钥 | 该服务的 API 凭据；本地无密钥服务可按服务要求留空 |
| 推理强度 | 关闭、低、中、高；需服务与模型支持对应参数 |
| 上下文窗口 | 模型上下文容量配置 |
| 最大输出 token | 单次模型输出上限，不可大于上下文窗口 |

生产服务地址需使用 HTTPS；本地回环服务可以使用 HTTP。不要把用户名、密码、API 密钥或查询参数写进接口地址。模型 ID 不预设成某个产品内的显示名：同名模型在不同服务中的 API 标识和可用性可能不同。

保存后，API 密钥输入框会清空；留空再次保存会保留已有密钥。应用使用 Electron `safeStorage` 与操作系统密钥服务加密，前端只知道是否已有密钥。若系统安全存储不可用，界面会显示具体错误，不会降级为明文保存。

点击「测试已保存连接」会读取服务的模型列表，并确认配置的模型 ID 存在。它不验证模型能否正确调用工具、不验证推理参数兼容性，也不保证真实任务成功。保存后应先用一个小型可信项目完成一次真实任务。

API 模式使用 OpenAI 兼容 Chat Completions，Codex 模式使用固定官方 Responses 地址。其他 Responses 服务或厂商专属参数不能仅改名称就视为已兼容。真实工具调用和安装后的验收结果见 [验证记录](VALIDATION.md)。

## 3. 界面语言和回复语言

「设置 → 通用」提供「跟随系统 / 简体中文 / English」。首次跟随系统：中文系统使用简体中文，其他语言使用 English。左下角也能直接切换。

界面语言只控制导航、按钮、状态、日期、提示和设置。切换时保留当前任务、所选节点、面板、草稿和执行状态；不会重启任务，也不会调用模型翻译已有内容。

用户目标、节点标题与目标、代码、文件路径、命令、模型历史回复、工具输出和原始事件保留原文。「模型回复语言」单独选择跟随任务、中文或 English，影响后续模型运行。

## 4. 选择项目

点击「打开项目」或项目分组旁的加号，选择 Git 仓库根目录。创建任务前需要满足：

- 仓库已有至少一个提交，能解析 `HEAD`。
- 原工作区干净，没有已修改或未跟踪文件。
- 当前版本中的文件为普通文件，不使用符号链接或 Git 子模块。

应用从选定仓库的 `HEAD` 创建独立工作区。后续修改写入该任务工作区，不直接覆盖原项目的未提交文件。遇到不满足条件的项目时，界面会报告原因；应先在原项目整理或提交自己的修改，再重新创建任务。

任务工作区跨多次尝试保留。结束或取消任务不会自动合并回原分支，也不会推送到远程。需要交付时先审阅产物和报告，再自行选择应用变更的方式。

## 5. 快速会话、计划任务和验收条件

应用默认打开新会话页。选择项目、输入消息后点击「发送」，即可使用已保存的模型配置开始；项目优先沿用当前或最近使用的项目，不需要每次重新填写验收、预算和执行方式。

一轮回复结束后，在底部输入框继续发送消息。Enter 发送，Shift+Enter 换行，也可使用 Command/Ctrl+Enter；输入法选词期间不会发送。同一会话保留原工作区、消息、历次计划及工具记录。运行中发送新消息会先停止旧 Run 并等待收尾，再按新消息重新规划；遇到未查明效果时仍须先查证，发送失败会保留输入。

快速会话默认自动执行已校验的计划。没有自动检查的步骤显示「已结束」，会话显示「等待下一条消息」，不表示结果已经验收通过。配置了固定检查时，检查仍会真实执行；失败会阻塞，不会因使用会话模式而跳过。

每条新消息使用一份轮数预算；累计用量与历史不会清零。暂停、恢复、重试和编辑验收都不会补发预算。完整对话保存到本地，模型上下文带入最近最多 24 条消息、总计最多 64,000 个字符，并记录省略条数；当前尚未自动压缩更早的对话，必要时在新消息中补充仍需保留的约束。

需要有限持续或维护任务时，展开「高级选项」，将交互模式切换为「计划任务」，再设置目标、验收和周期。计划任务保留修改目标前的影响预览与人工验收流程。快速会话不能设置周期或到期时间。

执行方式有两种：

| 方式 | 行为 |
| --- | --- |
| 在授权范围内自动执行 | 计划通过校验并保存后开始执行 |
| 先审阅计划 | 停在「计划就绪」，点击「开始执行」后继续 |

无论选择哪一种，任务都会先规划。规划阶段只允许查看文件、列目录和检索文本；不会因为收到一份草稿就开始修改代码。

### 设置检查命令

点击「添加检查」，填写名称、参数数组和受保护路径。例如：

```json
["node", "check.mjs"]
```

或使用项目已经存在的测试命令：

```json
["npm", "test", "--", "api"]
```

这里是 JSON 参数数组，不是整段 shell 命令。每个参数单独作为一个数组元素。不要依赖用户 shell 配置、环境中的密钥或交互式登录。

「受保护路径」每行填写一个相对任务工作区的文件或目录。用于固定验收脚本和相关定义，防止 Agent 通过修改检查本身获得通过结果。路径必须位于工作区内，不能指向 `.git` 或上级目录。

同一批检查结果与一个工作区摘要和任务/计划版本绑定。检查之间或最终确认前文件变化时，该批验收失效。如果检查修改了纳入证据的项目文件，该次验证不会被当成有效通过。选择可以稳定复验的命令，避免把会重写源码、更新快照或改变验收定义的操作混入验收命令。

计划任务中的单次或有限持续任务不填检查命令也可以创建，但界面会显著提示没有自动验收。模型完成节点后，任务仍会等待你审阅并接受当前工作区；模型说“完成”不会直接替代人工验收。持续维护必须填写至少一个固定检查，不能用没有检查的任务持续报告正常。快速会话无检查时只结束本轮回复，不设置验收通过状态。

只运行可信仓库和命令。macOS 文件与网络沙箱不是虚拟机；刻意脱离进程组的后台进程可能无法随任务回收。不要将本工具用于执行来源不明或恶意项目。

### 预算

每项任务设定最大模型轮次和单次运行时间。计划任务跨运行累计轮次，快速会话按本条消息累计；达到上限会停止推进并给出原因，不会无限循环。时间上限限制一次有界运行，工具命令另有执行超时。

界面目前允许最多 500 轮、单次运行最多 60 分钟。计划任务预算不足需要重新安排任务；快速会话明确发送新消息后获得下一份预算，暂停、继续或重试均不补发预算。

## 6. 三个工作区

### 左侧项目与任务导航

项目分组可以折叠；项目下显示实际任务标题、状态和更新时间。搜索按任务标题和目标过滤。切换任务会读取该任务的快照和界面偏好，不会停止后台正在执行的任务。

「定时任务」只列出有限持续和维护任务，展示真实状态、下次检查时间与到期时间，以及与主对话、规划过程相同的等待/维护观察卡片。它不是独立云调度服务。

「内置能力」说明已接入的项目资料、上下文、工作区工具与固定检查。当前没有插件市场、动态安装或第三方插件执行入口。

### 中间对话、活动和变更

「对话」显示用户要求、模型可见回复、任务步骤、变更入口与待答决定。必要决定在这里回答，不需要先打开规划栏。

「任务步骤」显示整份当前计划与已验证数量，关闭规划栏仍能查看。展开步骤可看目标、声明输入、预期产物，以及实际运行记录。进度来自主进程的节点状态；模型说“完成”或一次 Run 结束不会自行增加已验证数量。

每次运行中的「本次运行输入」显示固定文件或前驱产物、来源 Run、原始字节与保存文本的摘要，以及已交给运行器的内容范围。展开可查看保存文本。缺失文件、空内容、部分交付和脱敏各有标记；范围不代表模型已经理解。后续节点覆盖同名文件也不会改变早期快照。输入覆盖未知表示可能存在未记录依赖，不能当作完整来源证明。

实际记录按尝试展示工具参数、输出、状态、起止时间、检查和产物。声明中的产物名称不表示文件已经产生；只有记录在当前 Run 的产物才展示为本次产出。重做、修改计划和同名节点的旧记录列入历史。已记录的决定和用户回答可回看；界面展示公开回复与证据，不展示或推测模型的隐藏思考。

「活动」按事件顺序显示实际运行记录。展开可查看原始文本、结构化数据、运行 ID 和节点关联。该视图和对话使用同一份已保存事件，不是另一套任务状态。

「变更」显示运行产生的变更产物。展开后可阅读内容和关联运行。产物可能是某次运行后的整体工作区差异，不能把每张卡片简单相加理解为互不重叠的补丁。

顶部提供暂停、继续、取消、报告导出和规划开关。控制按钮只发送受限桌面命令，状态以主进程返回和后续快照为准。

输入框用于补充或修改任务要求，发送动作会生成影响预览。当前不是独立于任务状态的自由聊天入口；无效命令或版本冲突会明确显示错误。

### 底部文件、终端和预览

文件、终端与预览可以独立切换、关闭，不会替换右侧规划。

| 面板 | 内容 |
| --- | --- |
| 文件 | 当前任务工作区的普通文件列表和只读内容；点击刷新可重新读取列表 |
| 终端 | 实际命令工具与固定检查的输出；不是任意 shell 输入框 |
| 预览 | 已产生文件、文本或差异产物的只读内容；不执行 HTML 或脚本 |

长文件、工具输出和差异有大小限制，截断时会注明。二进制文件没有文本预览。文件读取遇到越界路径、符号链接或证据规模超过限制时会拒绝读取并报告。

## 7. 右侧规划栏

右上角「规划」独立控制右侧栏。首次默认关闭，之后保存开关偏好。关闭只释放界面空间，任务继续运行，事件继续记录；重新打开会显示当前状态。

窗口较窄时，规划从右侧以抽屉展开。它不会移到对话下面。可点击关闭按钮、遮罩或按 Escape 关闭；抽屉打开时键盘焦点留在其中，关闭后回到规划按钮。

「过程」显示已提交的事实、约束、方案摘要、来源、草稿和计划修订记录。它展示模型写给用户的工作摘要，不展示或模拟模型隐藏思维链。

「步骤」在图和列表之间切换，两者使用同一组计划节点。图上连线表示依赖关系，不表示多 Agent 并行执行。当前只有一条活动任务运行。

点击节点可查看：

- **概览**：目标、输入、依赖、预期产物、检查定义与状态原因。
- **产物**：关联该节点的真实差异、文本或文件记录。
- **验证**：检查结果、输出、运行标识、时间与输入摘要。
- **历史**：每次尝试的状态、摘要和工具记录。

计划版本下拉可以查看旧计划。历史计划不复用当前节点绿灯；历史检查也不自动证明当前版本满足要求。节点的完成状态由协调器给出。

## 8. 改要求与局部重做

### 修改要求

在输入框写补充要求，然后点击向上箭头「预览需求变更」。应用先停止当前运行，查证工作区，再生成影响预览。

当前采用保守策略：新的任务目标会使原计划的全部节点失去完成依据，保留已有文件与历史，然后重新规划。界面显示的受影响范围来自主进程，前端不自行缩小影响。

点击「应用并继续」后保存新任务版本并启动相应工作。预览由主进程签发，并校验任务版本、计划、工作区及声明/实际读取文件的来源摘要；若期间文件或计划变化，旧预览不能继续应用，需要重新生成。

关闭影响对话框会保留暂停状态。想继续原要求，点击顶部「继续」。生成预览本身不是后台无副作用查询，因此不要把关闭预览理解为自动恢复。

### 修改验收条件

点击输入框下方的「编辑验收」，可修改检查标签、命令参数和受保护路径，也可添加或删除检查。字段格式与创建任务时相同，编辑表单本身不会替换已保存条件。点击「预览影响」后，应用停止当前运行，按检查 ID 展示修改前后的完整定义和受影响步骤。

确认「应用并继续」后生成新的任务版本、重新规划并使用新检查。旧计划、检查结果和命令记录仍保留其当时的定义；同 ID 检查改了名字或命令，也不会改写旧记录。确认前关闭预览会保留原检查并保持暂停，可点击「继续」按原条件推进。已确认提交的修订不会因关闭弹窗而撤销；后来输入的需求会保留。

删除全部自动检查后，单次或有限计划任务须等待你接受新版本的当前工作区；快速会话只结束本轮回复，不表示验收通过。持续维护不能删除最后一个检查。切换任务或任务版本变化后，请重新打开编辑器生成预览。尚未查明的效果仍须先处置，修改验收不能越过恢复门。

### 重做节点

在当前计划的节点概览点击「重做此步骤」。预览会列出该节点、不具复用资格的已有尝试及其依赖后继，并说明失效原因。输入和上下文仍适用的成功研究可保留原 Run；尚未运行且不受影响的节点保持待办。确认后受影响节点在当前文件基础上创建新尝试，后续输入变化仍会撤销复用资格。

这不会自动撤销工作区，不会恢复某个历史文件版本，也不会重放未知外部动作。若需要恢复文件，应先审阅自己的修改和历史差异。

## 9. 暂停、取消与恢复

「暂停」会请求停止当前运行，等待执行收尾，再保存暂停状态；它不是只停前端动画。「继续」先核对工作区与既有证据，再安排后续运行。

如果文件在上次验证后发生变化，相关完成依据会失效；未知、失败或中断节点需要重新执行和检查。当前采用保守的工作区摘要核对，不承诺自动证明复杂变更互不影响。

「取消任务」会要求一次明确确认。已保存文件和历史仍保留，取消后的任务不可继续。已完成和已到期任务同样不可直接恢复，后续工作应创建新任务。

正常退出 App 会停止运行并保留任务。若之前的所有者异常消失，重启后进行恢复检查；未查明的运行或动作标记为待确认，任务受阻，点击「继续」后，App 先查证确定性文件操作：实际文件的身份、内容和权限与写入前保存的预期结果一致时，保留文件并重新规划。工具记录会显示「已查证文件后置状态」，原操作仍保留未知状态；它不表示之前的操作必然执行过。其他情况展示恢复卡片，尚不启动新的执行。

1. 查看恢复证据中的动作回执和当前文件差异；涉及网络的命令还需核对外部结果。
2. 确认保留当前状态后，选择保留文件并重新规划；无法继续时选择停止任务。保留不代表原操作已经成功。
3. 如果文件或未知动作又有变化，旧决定会失效，需要重新查看证据。

未知命令未处置时，其他任务也暂不开始新效果。取消或到期任务可通过「查看未确认的操作影响」单独处置回执；处置不会重新启动终态任务。不要根据界面里留存的旧回复推断命令已经成功。

## 10. 单次、有限持续与维护任务

| 模式 | 运行方式 |
| --- | --- |
| 单次 | 规划、执行和验收；完成后结束 |
| 有限持续 | 观察指定本地文件，有尚未消费且满足条件的信息后继续；需要周期和未来到期时间 |
| 持续维护 | 初次开发验收后，只按周期运行固定检查，显示最近健康状态；至少一个固定检查 |

### 登记有限等待

1. 创建任务时选择「有限持续」，填写检查周期和未来到期时间。
2. 在目标中说明要等哪个来源、什么条件成立后继续，以及后续需要完成的开发工作。例如：“等待所选原项目的 `status/review.txt` 包含 `approved` 后，按文件中的要求更新示例；每 5 分钟观察一次。”
3. 查看模型生成的计划；模型通过结构化结果登记等待后，本次 Run 结束，界面出现「外部等待」卡片。仅在聊天中写“稍后再查”不会登记等待。
4. 在卡片核对实际来源、条件、最近内容、摘要、下次观察时间和所属任务/计划/运行。当前没有单独编辑 Wait 字段的表单；需要改变来源或条件时，通过修改任务要求并应用影响预览完成。

可用来源只有两种：

| 来源 | 实际读取位置 |
| --- | --- |
| 任务工作区文件（workspace_file） | 本任务独立工作区内的相对路径 |
| 原项目文件（project_file） | 创建任务时选定的原 Git 项目内的相对路径 |

原项目的观察内容会带给下一次模型运行，但不会自动复制到任务工作区，也不会自动拉取提交、合并或变基。来源必须是可读取的普通文本文件，最多 32,000 字符；绝对路径、上级目录、`.git`、符号链接、目录和超大文件不作为有效观察。推荐用小型状态文件，不要指定持续增长的日志。

| 等待条件 | 含义 |
| --- | --- |
| 内容变化（changed） | 与该次 Run 和工具收尾后读取的基线不同；删除已有文件也算变化 |
| 文件存在（exists） | 路径对应可读取的普通文件 |
| 包含文本（contains） | 完整文本包含指定的字面文本，区分大小写；不是正则表达式 |

模型登记的 `minutes` 是这次 Wait 的实际观察间隔，可与创建任务时填写的周期不同，以卡片下次观察时间为准。changed 使用收尾后的基线，因此任务刚写下的内容不会立刻唤醒自己。exists/contains 如果登记时已满足，可以立即推进一次；同一节点连续等待同一来源、条件和相同内容时，不再触发模型。

去重只比较每组来源的最近消费状态。实际观察到 A → B → A → B 可以再次推进；明确观察到条件不满足后又恢复为相同满足内容，也可以再次推进。只有不可读取的 unknown 不算条件已变成不满足。应用新的任务目标、确认重做，或完成保留并重新规划的恢复处置后，会开始新的消费记录，历史仍保留。卡片在当前 Wait 确有 consumedAt 时显示「消费时间」，不会根据“条件满足”推算消费时间。

条件未满足、信息连续重复时，只读取来源并安排下一次观察。文件缺失与不可读取不同：缺失通常保持等待；权限问题、来源变成目录或符号链接、超大内容、来源根目录被替换时记录 unknown。恢复来源后可等下一次观察，或暂停后点击「继续」立即重新观察；「继续」不会绕过条件或未知效果恢复门。没有来源信息的旧版本等待会阻塞，需要修改要求以登记新等待。

来源消费后，App 在后续运行、工具准入、计划发布、决定接受和验收时重新核对。如果来源已变化或无法确认，会阻止继续；先查看实际来源，再明确修改要求或重试，不会继续沿用旧的合格内容。

### 查看维护结果和发起修复

创建维护任务时先填写稳定、可重复运行的固定检查和受保护路径。首次任务仍经过规划、开发和最终验收；之后的周期只运行这些检查，产生专门的「维护验证」运行，不重做之前的写节点，也不调用模型解释每次定时到期。

- healthy：这次批次在同一份当前输入上全部通过，卡片记录检查时间、输入摘要和批次。
- unhealthy：固定检查有明确失败。查看对应回执，可自行修复后等待下一次复验；需要 Agent 修复时，修改任务要求或明确重做相关步骤。
- unknown：检查中断、来源在验证中变化或当前状态无法确认。先查看原因；如果有未知命令效果，完成恢复卡片的查证和处置后才能继续。

健康状态表示最近一次检查结果，不保证之后文件始终正常。周期复验会继续观察当前文件；普通「继续」对已有维护记录只请求重新检查，不授权自动修复。检查仍会实际执行命令，应使用可信、稳定的检查；改变项目文件的检查不能获得有效的通过记录。维护验证不产生模型 token，用量汇总会与缺失用量的模型运行区分。

### 退出、休眠与观察缺口

应用依赖本机进程和定时器。关闭窗口在 macOS 上不一定退出 App；使用应用退出命令才会进入完整关闭流程。机器睡眠、进程退出期间没有观察。重新启动或恢复运行后的扫描只补查一次当前来源/检查，不按每个错过的周期重跑；卡片显示漏过间隔数、上次观察时间和缺口说明，缺口期间没有可追溯的观察结果。

任务截止后停止推进。等待和 healthy/unhealthy/unknown 维护状态都可用顶部「暂停」停止排期；暂停后由用户继续，不能被到期扫描自动恢复。等待观察不消耗模型轮次，随后实际 Run 仍受原累计预算约束。维护复验受单次执行超时和任务期限约束，不新增模型轮次。多个任务共用一条执行队列。

当前仅支持上述本地来源，没有直接连接 CI、webhook 或云端调度。本轮来源撤销和消费去重反例已通过回归、全套检查、独立复核及实际打包态验证；真实远端模型和真实休眠/强杀验收仍未完成。整体计划、todo、工具调用和决定逐步展示的强化也仍在继续；完整状态见 [完成度审查](COMPLETION-AUDIT.md)。

## 11. 导出与交付

顶部「导出报告」打开操作系统保存对话框，生成 Markdown 文件，包含目标、任务版本、计划版本、动作回执、决定与处置、检查结果、产物和事件记录。等待与维护单独保存最近观察、消费字段和观察事件历史；检查条目含批次、Task/Plan/Run 身份及关联的观察摘要。

报告反映导出时已保存的数据。长输出或产物可能已在采集时截断，报告不是完整文件备份。新声明文件产物必须是完整快照；旧 diff 和工具输出仍可能截断。报告另列每次 Run 的固定输入、实际读取和身份。报告可能包含项目代码、命令输出或任务内容，分享前应按项目要求审阅。

App 当前不会替用户项目自动创建提交、PR、合并、推送或部署。对文件的最终交付仍需审查补丁并按自己的开发流程完成。

## 12. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 模型 ID 校验失败 | 查服务商的实际模型列表，保存准确 ID；不要只填桌面产品显示名 |
| 模型列表检查通过，任务仍失败 | 查看活动与错误，核对工具调用、推理强度和 Chat Completions 参数兼容性 |
| 创建任务提示工作区不干净 | 先在原项目提交或另存自己的修改，再重新创建任务 |
| 沙箱不可用 | 当前需要 macOS `sandbox-exec`；检查外层运行环境权限，不绕开应用的沙箱门槛 |
| 命令找不到依赖或凭据 | 执行环境不加载用户配置和凭据；让项目使用明确、可复现的依赖和命令 |
| 检查通过文本仍标为失败 | 核对退出状态和检查前后摘要；检查修改文件会使验证无效 |
| 修改要求后任务停住 | 影响预览会暂停任务；应用预览或按「继续」恢复原要求 |
| 没有自动检查，任务等待决定 | 在主对话审阅产物并明确接受或拒绝当前工作区 |
| 等待条件满足但没有再次调用模型 | 连续重复同一来源信息不触发；明确观察到新变化或应用新的工作要求后可再次推进 |
| 已消费来源变化后任务被阻止 | 查看来源，再明确修改要求或重试；不能通过继续沿用旧的合格内容 |
| 外部等待显示 unknown | 查看来源错误，检查路径类型、权限、大小和原项目是否被替换；恢复后重新观察 |
| 原项目文件变了，任务文件没变化 | project_file 只提供观察数据，不自动同步文件；明确后续需要应用哪些变化 |
| 维护失败后没有自动修代码 | 周期任务只复验；通过修改要求或重做步骤明确发起修复 |
| 出现漏过周期提示 | 该时段没有观察；App 已合并补查当前状态，不会重放每个旧周期 |
| 旧任务预算耗尽 | 查看已完成工作，缩小或重新安排目标，创建具有新预算的任务 |
| 规划内容仍是英文 | 界面语言不翻译任务原文；另行设置后续模型回复语言 |

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

UI 测试使用实际前端和可控 IPC 测试替身，验证双语、状态保留、右侧抽屉、影响确认、表单和工具读取接线。核心、pi、执行沙箱及真实模型需要各自的集成验证；不能把某一层通过当成整个系统已经兼容所有模型和项目。
