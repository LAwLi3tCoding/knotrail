# Knotrail 用户指南

本文描述仓库当前实现。Knotrail 在本地保存任务和证据，通过 pi SDK 调用配置的模型；界面上的状态来自主进程保存的任务快照，不由动画或聊天文本推算。

## 1. 安装与启动

当前执行平台是 macOS。准备 Git、Node.js 24 或更新版本，以及原生依赖编译所需的开发工具。先安装依赖，再启动：

```sh
npm ci
npm run dev
```

`dev` 先构建前端、Electron 主进程、pi 工作进程和执行助手，再启动应用。它不是热更新服务器，修改源码后需要重新运行。

已经构建过时可以运行 `npm start`。如需重新生成产物，先运行 `npm run build`。`npm run package` 会生成未签名的 macOS 应用目录，不包含公证、安装器或自动更新。

应用默认使用 Electron 提供的本机应用数据目录，保存 SQLite 状态、密钥密文、工作区、pi 会话与报告。开发和隔离测试可以通过 `KNOTRAIL_DATA_DIR` 指定另一个数据目录。不要把真实任务数据、密钥或会话目录提交到代码仓库。

同一数据目录只能有一个状态所有者。若启动提示已有所有者，应先确认原应用或任务是否仍运行，不要删除锁文件来绕开运行中的任务。

## 2. 首次配置模型

进入左下角「设置 → 模型」：

| 字段 | 用途 |
| --- | --- |
| 接口地址 | OpenAI 兼容 Chat Completions 服务的基础 URL |
| 模型 ID | 服务商实际提供、支持工具调用的准确 ID |
| API 密钥 | 该服务的 API 凭据；本地无密钥服务可按服务要求留空 |
| 推理强度 | 关闭、低、中、高；需服务与模型支持对应参数 |
| 上下文窗口 | 模型上下文容量配置 |
| 最大输出 token | 单次模型输出上限，不可大于上下文窗口 |

生产服务地址需使用 HTTPS；本地回环服务可以使用 HTTP。不要把用户名、密码、API 密钥或查询参数写进接口地址。模型 ID 不预设成某个产品内的显示名：同名模型在不同服务中的 API 标识和可用性可能不同。

保存后，API 密钥输入框会清空；留空再次保存会保留已有密钥。应用使用 Electron `safeStorage` 与操作系统密钥服务加密，前端只知道是否已有密钥。若系统安全存储不可用，界面会显示具体错误，不会降级为明文保存。

点击「测试已保存连接」会读取服务的模型列表，并确认配置的模型 ID 存在。它不验证模型能否正确调用工具、不验证推理参数兼容性，也不保证真实任务成功。保存后应先用一个小型可信项目完成一次真实任务。

当前运行协议是 OpenAI 兼容 Chat Completions。需要 Responses API 专属功能、不同身份验证方式或厂商专属参数的端点，不能仅改名称就视为已兼容。桌面产品的订阅不等于这个应用可使用的 API 凭据。

## 3. 界面语言和回复语言

「设置 → 通用」提供「跟随系统 / 简体中文 / English」。首次跟随系统：中文系统使用简体中文，其他语言使用 English。左下角也能直接切换。

界面语言只控制导航、按钮、状态、日期、提示和设置。切换时保留当前任务、所选节点、面板、草稿和执行状态；不会重启任务，也不会调用模型翻译已有内容。

用户目标、节点标题与目标、代码、文件路径、命令、模型历史回复、工具输出和原始事件保留原文。「模型回复语言」单独选择跟随任务、中文或 English，影响后续模型运行。

## 4. 选择项目

点击「打开项目」或项目分组旁的加号，选择 Git 仓库根目录。创建任务前需要满足：

- 仓库已有至少一个提交，能解析 `HEAD`。
- 原工作区干净，没有已修改或未跟踪文件。
- 当前版本中的文件为普通文件，不使用符号链接或 Git 子模块。

应用从选定仓库的 `HEAD` 创建独立工作区。后续修改写入该任务工作区，不直接覆盖原项目的未提交文件。遇到不满足条件的项目时，界面会报告原因；应先在原项目整理或提交自己的修改，再重新创建任务。

任务工作区跨多次尝试保留。结束或取消任务不会自动合并回原分支，也不会推送到远程。需要交付时先审阅产物和报告，再自行选择应用变更的方式。

## 5. 创建任务和验收条件

点击「新任务」，选择项目并填写目标。目标应说明要改什么、必须保持什么，以及什么结果可以算完成。

执行方式有两种：

| 方式 | 行为 |
| --- | --- |
| 在授权范围内自动执行 | 计划通过校验并保存后开始执行 |
| 先审阅计划 | 停在「计划就绪」，点击「开始执行」后继续 |

无论选择哪一种，任务都会先规划。规划阶段只允许查看文件、列目录和检索文本；不会因为收到一份草稿就开始修改代码。

### 设置检查命令

点击「添加检查」，填写名称、参数数组和受保护路径。例如：

```json
["node", "check.mjs"]
```

或使用项目已经存在的测试命令：

```json
["npm", "test", "--", "api"]
```

这里是 JSON 参数数组，不是整段 shell 命令。每个参数单独作为一个数组元素。不要依赖用户 shell 配置、环境中的密钥或交互式登录。

「受保护路径」每行填写一个相对任务工作区的文件或目录。用于固定验收脚本和相关定义，防止 Agent 通过修改检查本身获得通过结果。路径必须位于工作区内，不能指向 `.git` 或上级目录。

检查结果与执行时的工作区摘要绑定。如果检查修改了纳入证据的项目文件，该次验证不会被当成有效通过。选择可以稳定复验的命令，避免把会重写源码、更新快照或改变验收定义的操作混入验收命令。

不填检查命令也可以创建任务，但界面会显著提示没有自动验收。模型完成节点后，任务仍会等待你审阅并接受当前工作区；模型说“完成”不会直接替代人工验收。

只运行可信仓库和命令。macOS 文件与网络沙箱不是虚拟机；刻意脱离进程组的后台进程可能无法随任务回收。不要将本工具用于执行来源不明或恶意项目。

### 预算

每项任务设定最大模型轮次和单次运行时间。轮次限制累计在任务上；达到上限会停止推进并给出原因，不会无限循环。时间上限限制一次有界运行，工具命令另有执行超时。

界面目前允许最多 500 轮、单次运行最多 60 分钟。预算不足需要重新安排任务；界面不提供在运行中无限追加预算的按钮。

## 6. 三个工作区

### 左侧项目与任务导航

项目分组可以折叠；项目下显示实际任务标题、状态和更新时间。搜索按任务标题和目标过滤。切换任务会读取该任务的快照和界面偏好，不会停止后台正在执行的任务。

「定时任务」只列出有限持续和维护任务，展示真实状态、下次检查时间与到期时间。它不是独立云调度服务。

「内置能力」说明已接入的项目资料、上下文、工作区工具与固定检查。当前没有插件市场、动态安装或第三方插件执行入口。

### 中间对话、活动和变更

「对话」显示用户要求、模型可见回复、紧凑工具记录、变更入口与待答决定。必要决定在这里回答，不需要先打开规划栏。

「活动」按事件顺序显示实际运行记录。展开可查看原始文本、结构化数据、运行 ID 和节点关联。该视图和对话使用同一份已保存事件，不是另一套任务状态。

「变更」显示运行产生的变更产物。展开后可阅读内容和关联运行。产物可能是某次运行后的整体工作区差异，不能把每张卡片简单相加理解为互不重叠的补丁。

顶部提供暂停、继续、取消、报告导出和规划开关。控制按钮只发送受限桌面命令，状态以主进程返回和后续快照为准。

输入框用于补充或修改任务要求，发送动作会生成影响预览。当前不是独立于任务状态的自由聊天入口；无效命令或版本冲突会明确显示错误。

### 底部文件、终端和预览

文件、终端与预览可以独立切换、关闭，不会替换右侧规划。

| 面板 | 内容 |
| --- | --- |
| 文件 | 当前任务工作区的普通文件列表和只读内容；点击刷新可重新读取列表 |
| 终端 | 实际命令工具与固定检查的输出；不是任意 shell 输入框 |
| 预览 | 已产生文件、文本或差异产物的只读内容；不执行 HTML 或脚本 |

长文件、工具输出和差异有大小限制，截断时会注明。二进制文件没有文本预览。文件读取遇到越界路径、符号链接或证据规模超过限制时会拒绝读取并报告。

## 7. 右侧规划栏

右上角「规划」独立控制右侧栏。首次默认关闭，之后保存开关偏好。关闭只释放界面空间，任务继续运行，事件继续记录；重新打开会显示当前状态。

窗口较窄时，规划从右侧以抽屉展开。它不会移到对话下面。可点击关闭按钮、遮罩或按 Escape 关闭；抽屉打开时键盘焦点留在其中，关闭后回到规划按钮。

「过程」显示已提交的事实、约束、方案摘要、来源、草稿和计划修订记录。它展示模型写给用户的工作摘要，不展示或模拟模型隐藏思维链。

「步骤」在图和列表之间切换，两者使用同一组计划节点。图上连线表示依赖关系，不表示多 Agent 并行执行。当前只有一条活动任务运行。

点击节点可查看：

- **概览**：目标、输入、依赖、预期产物、检查定义与状态原因。
- **产物**：关联该节点的真实差异、文本或文件记录。
- **验证**：检查结果、输出、运行标识、时间与输入摘要。
- **历史**：每次尝试的状态、摘要和工具记录。

计划版本下拉可以查看旧计划。历史计划不复用当前节点绿灯；历史检查也不自动证明当前版本满足要求。节点的完成状态由协调器给出。

## 8. 改要求与局部重做

### 修改要求

在输入框写补充要求，然后点击向上箭头「预览需求变更」。应用先停止当前运行，查证工作区，再生成影响预览。

当前采用保守策略：新的任务目标会使原计划的全部节点失去完成依据，保留已有文件与历史，然后重新规划。界面显示的受影响范围来自主进程，前端不自行缩小影响。

点击「应用并继续」后保存新任务版本并启动相应工作。预览由主进程签发，并校验任务版本、计划与工作区；若期间文件或计划变化，旧预览不能继续应用，需要重新生成。

关闭影响对话框会保留暂停状态。想继续原要求，点击顶部「继续」。生成预览本身不是后台无副作用查询，因此不要把关闭预览理解为自动恢复。

### 重做节点

在当前计划的节点概览点击「重做此步骤」。预览会使该节点及所有依赖它的下游节点失效，其他节点按实际依赖保留。确认后在当前文件基础上创建新的尝试并重新检查。

这不会自动撤销工作区，不会恢复某个历史文件版本，也不会重放未知外部动作。若需要恢复文件，应先审阅自己的修改和历史差异。

## 9. 暂停、取消与恢复

「暂停」会请求停止当前运行，等待执行收尾，再保存暂停状态；它不是只停前端动画。「继续」先核对工作区与既有证据，再安排后续运行。

如果文件在上次验证后发生变化，相关完成依据会失效；未知、失败或中断节点需要重新执行和检查。当前采用保守的工作区摘要核对，不承诺自动证明复杂变更互不影响。

「取消任务」会要求一次明确确认。已保存文件和历史仍保留，取消后的任务不可继续。已完成和已到期任务同样不可直接恢复，后续工作应创建新任务。

正常退出 App 会停止运行并保留任务。若之前的所有者异常消失，重启后进行恢复检查；未查明的运行或动作标记为待确认，任务受阻，需审阅历史后显式继续。不要根据界面里留存的旧回复推断命令已经成功。

## 10. 单次、有限持续与维护任务

| 模式 | 运行方式 |
| --- | --- |
| 单次 | 规划、执行和验收；完成后结束 |
| 有限持续 | 允许外部等待后重新运行，到期后停止；需要周期和未来到期时间 |
| 持续维护 | 验收正常后按周期重新核对，显示下次检查时间 |

应用依赖本机进程和定时器。关闭窗口在 macOS 上不一定退出 App；使用应用退出命令才会进入完整关闭流程。机器睡眠、进程退出、网络不可用期间，不应期待云端继续观察或执行；回来后需核对当前状态。

检查失败会保留证据并停止或等待处理，当前不是无限自动修复服务。预算仍然生效，不因定时触发而重置。多个任务共用一条执行队列，计划图的并列依赖也不改变这个限制。

## 11. 导出与交付

顶部「导出报告」打开操作系统保存对话框，生成 Markdown 文件，包含目标、任务版本、计划版本、检查结果、产物和事件记录。

报告反映导出时已保存的数据。长输出或产物可能已在采集时截断，报告不是完整文件备份。报告可能包含项目代码、命令输出或任务内容，分享前应按项目要求审阅。

App 当前不会替用户项目自动创建提交、PR、合并、推送或部署。对文件的最终交付仍需审查补丁并按自己的开发流程完成。

## 12. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 模型 ID 校验失败 | 查服务商的实际模型列表，保存准确 ID；不要只填桌面产品显示名 |
| 模型列表检查通过，任务仍失败 | 查看活动与错误，核对工具调用、推理强度和 Chat Completions 参数兼容性 |
| 创建任务提示工作区不干净 | 先在原项目提交或另存自己的修改，再重新创建任务 |
| 沙箱不可用 | 当前需要 macOS `sandbox-exec`；检查外层运行环境权限，不绕开应用的沙箱门槛 |
| 命令找不到依赖或凭据 | 执行环境不加载用户配置和凭据；让项目使用明确、可复现的依赖和命令 |
| 检查通过文本仍标为失败 | 核对退出状态和检查前后摘要；检查修改文件会使验证无效 |
| 修改要求后任务停住 | 影响预览会暂停任务；应用预览或按「继续」恢复原要求 |
| 没有自动检查，任务等待决定 | 在主对话审阅产物并明确接受或拒绝当前工作区 |
| 旧任务预算耗尽 | 查看已完成工作，缩小或重新安排目标，创建具有新预算的任务 |
| 规划内容仍是英文 | 界面语言不翻译任务原文；另行设置后续模型回复语言 |

## 13. 开发者验证

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

UI 测试使用实际前端和可控 IPC 测试替身，验证双语、状态保留、右侧抽屉、影响确认、表单和工具读取接线。核心、pi、执行沙箱及真实模型需要各自的集成验证；不能把某一层通过当成整个系统已经兼容所有模型和项目。
