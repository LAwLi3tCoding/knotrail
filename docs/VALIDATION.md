## Codex 登录与步骤展示覆盖

- 只读登录缓存，拒绝符号链接、FIFO、非普通文件、超限/非法 JSON、错误模式、无效或过期 JWT；每个 Run 重新读取轮换后的 access token，不返回刷新凭据或改写源文件。
- 固定官方 SSE/POST 地址、禁止自定义收件端点与重定向；两轮 Responses 保留工具调用关联。到期终止活动 Run，Renderer 不能提交自己的到期时间。
- 合成凭据在分片文本、工具参数/结果、控制结果、事件、错误及实际 pi session 中不泄露。
- 仅指定的响应头前连接中断最多重试两次；到期和取消阻止下一次请求。独立实际 Worker 实验确认一次网络重试后本地工具仅执行一次，并记录 `provider.retry` 与 `usage.partial=true`。HTTP 500 和响应头后的断流独立实验均只有一次请求、没有重试。
- Tracker 使用 NodeState 而非 Run 文本计算进度；重做、换版本和同名节点旧产物保留为历史。工具参数由 runId/toolCallId 关联，决定及回答可回看。14 项 UI 包含 360px 展开记录与当前/历史计划切换；本轮截图验收为浅色模式。
- 最新打包态模拟服务链通过：两次固定检查、右规划与主对话 Tracker、中英切换、安全存储、独立工作区均正常，Renderer 错误为 0。它使用真实 Electron、pi 和沙箱，模型响应仍为本地脚本。

## 固定验收修订

- `task.previewRevision` 支持仅改 checks 或同时修改 objective；预览先停止旧运行，应用前保留原定义，完整预览不得篡改。省略 checks 与显式空数组分别表示保留与删除，维护任务拒绝空检查。
- 四项新增 Core 回归覆盖新旧 CheckSpec、Plan、检查摘要和人工决定的身份，旧 Run 迟到工具请求被拒绝，旧完成资格不会继承。真实 SQLite 触发器使事务最后一项 requestId 写入失败，确认任务、历史及预览消费全部回滚；再用同一请求正常提交并重新读取数据库。这是受控事务故障，不是磁盘满或真实 I/O 故障。
- Renderer 复用新任务检查编辑字段，在应用前显示旧新标签、命令和保护路径；同 ID 的历史检查按原 TaskRevision 取定义，legacy 缺失定义明确标记未记录。取消、陈旧版本、跨任务迟到响应、维护删空、双语、窄屏和弹窗内错误均有 UI 回归。
- 独立审查先后复现取消编辑后迟到响应重开旧预览、迟到 Apply 关闭新预览并清空新草稿的两项问题。Preview 与 Apply 现在共用操作序号、任务选择序号及 taskId 校验，迟到成功或失败不再覆盖新界面；宿主快照仍正常接收。清空输入前还核对发起预览时的原始草稿。两个原始反例文件未修改，分别重跑 1/1 通过，独立审查结论为 pass。
- 新增十项 UI 回归覆盖编辑、历史、陈旧版本、三个取消入口、迟到成功/失败及草稿保留；全套 24/24 通过。取消预览不会隐式恢复任务，也不会提前替换验收定义。
- 增强后的开发态与最新打包态真实桌面链路均已通过：第一版 ready 时无写入，通过界面修改检查并确认，第二版重新规划到 ready 后才开始执行；新增保护文件的写入被沙箱拒绝，目标文件写入成功，两次固定检查通过。导出包含两版验收定义，Renderer 错误为 0；模型响应来自受控本地协议服务。打包后的九个应用构建文件与当前 dist 逐一比较 SHA-256 一致，截图确认纯文本 Knotrail 和右侧规划栏。

## 任务与状态覆盖

- 创建请求持久去重，requestId 不能对应不同参数。
- 规划阶段写请求被 Main 拒绝；审阅模式 ready 前不修改工作树。
- 草稿允许不完整；最终计划拒绝环、未知依赖、重复 ID 和遗漏固定检查。
- 同一批次的节点与最终验收绑定 TaskRevision、Plan、检查定义和文件摘要；计划任务无命令时要求 typed 人工验收，快速会话仅结束本轮回复。
- 规划候选提交后至 Worker 收尾的文件变化阻止 Plan 发布；Ready 后首次执行前变化要求重新规划。
- 检查之间和最终检查回执之后的文件变化阻止成功，不拼接不同来源的 pass。
- 修改文件后旧人工验收失效；修改目标保留历史并提升版本。
- 影响预览由 host 签发、检查原件并一次性消费，不能换请求 ID 重放。
- 取消后的旧决定不能重启任务；截止日过去后的无效回答不改变既有终态。
- 最后一个允许的 turn 可以完成任务，不要求虚假的额外轮数。
- Run 超时取消已经准入的父层工具，并阻止自动重试。
- 绝对截止时间作用于 Run 和最终验收，过期任务不能落成 completed。
- 崩溃中未确认操作变为 unknown；Resume、修改、重试和定时唤醒均经过恢复门。
- pending 保存失败时效果调用数为零；文件已写但结果回执保存失败时中止准入，不能以新 toolCallId 重发。
- 人工处置绑定动作集合、版本与工作区摘要，来源变化或处置写入失败不能解锁。
- 跨任务查证未知命令不会把取消任务改成可恢复状态；取消任务可单独处置未知回执，状态保持 cancelled、Run 数不增加；未知命令处置前阻止其他任务效果。
- 恢复卡片展示证据与双语宿主选项，模型原文保留；旧 Plan/Run 或缺绑定检查标历史，用量未上报显示不可用或记录不完整。

## 长任务来源与维护覆盖

长任务来源与维护阶段的 Core 共 38 项、真实 pi 协议 7 项；后续认证与验收修订回归计入上表当前总数。

- Wait 登记相对文件来源和明确条件，未满足、不可读或重复信息时只观察，不增加模型轮数；漏过多次检查合并一次观察，并保留漏查时间与周期数。
- Run 自己写文件后才建立 changed 基线；已满足的 exists/contains 可首次触发。暂停/继续不会绕过重复信息抑制，轮数预算耗尽后新信息也不会创建模型 Run。
- 缺失文件是已知的 null 摘要；目录、悬空符号链接、权限不足、超限内容和来源根目录被替换记为 unknown，不能把截断内容当完整事实。
- 已消费来源在恢复前或 Run 中被撤销时，先阻止模型/工具准入；固定检查之后来源变化也不能提交旧成功。
- 每个来源只保存最近消费摘要，真实 A→B→A→B 和“不满足→相同满足内容”仍可推进。用户明确修改目标、重试或恢复处置会重置消费状态，自动重复 Wait 继续去重。
- 持久边界重建覆盖漏过周期后补查、消费已提交而下一个 Run 尚未开始两个窗口；这些是数据库状态重建测试，不是操作系统强杀实验。
- 维护必须配置固定检查；专用 verification Run 不调用模型、不重放编辑节点。稳定检查失败记 unhealthy，检查时输入变化、无确定退出状态记 unknown；未知命令在后续准入要求处置。
- pi 真协议验证缺少来源/条件的 wait 被拒绝，合法 wait 接受后同一批次的后续 write 不会调用宿主工具。

## 真实桌面链路

`tests/desktop-smoke.mjs` 启动临时 Git 项目与独立 App 数据目录，使用本地 OpenAI 协议服务给出可控模型响应。模型循环仍是真实 pi SDK，没有用测试替身代替 Runner 或 SandboxExecutor。

默认受控流程依次读取文件、提交第一版计划、在 ready 检查零修改、通过真实界面修改固定验收并审阅旧新定义、提交第二版计划，再开始执行。执行先尝试写入新增保护文件并验证被拒绝，然后修改目标文件、运行节点与最终两次固定比较命令、完成并保存两版定义及报告。随后从默认入口创建快速会话、发送追问，检查同工作区两轮历史与前文传入真实 pi 请求。检查源仓库没有变化、Renderer 错误为零、规划面板确实位于右侧，以及中英文切换。真实 Codex 分支保留单节点原始任务，不由脚本模拟修订或追问。

脚本创建并清理临时 Git 项目，要求模型先提交计划再改文件，只有独立固定检查通过才报告 passed。API 请求可能产生费用；它不是固定响应的 HTTP fixture。

## 无凭据连接诊断

额外六次有界探测比较 Node fetch、Electron 内置运行时及系统 curl 的 HTTP/TLS 组合，均只向固定官方地址发送无凭据空 POST。观测到 Node 在 `undici:client:connectError` 出现 ECONNRESET，尚未产生 `connected` 或 `sendHeaders`；另一次 curl 已完成 TCP 连接但 TLS 握手未完成，报 SSL_ERROR_SYSCALL。部分组合返回 401，只证明未鉴权请求抵达服务。TLS 1.2 也发生握手失败，单次 HTTP/2 或 Electron 成功不足以证明更换传输栈有效。未因此降低证书校验、增加重试上限或修改网络配置；网络故障仍未修复。
